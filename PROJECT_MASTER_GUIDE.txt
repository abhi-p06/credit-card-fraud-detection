1.1 Project Title:
Credit Card Fraud Detection using SVM Classification with Data Preprocessing

1.2 Problem Being Solved:
When credit card transactions occur, financial institutions must distinguish between legitimate customer purchases and unauthorized fraudulent operations. In modern automated economies, billions of card transactions occur daily. Criminals use stolen credentials, skimming devices, identity theft, and online data breaches to execute fraudulent charges. 

Manual inspection of every purchase is mathematically and operationally impossible. If an institution delays transaction clearance to inspect records manually, legitimate customer checkouts freeze, disrupting commerce. Conversely, if no automated defense exists, financial losses, chargebacks, and consumer distress skyrocket.

This project solves that challenge by constructing an automated, data-driven machine learning classifier that examines numerical attributes of each transaction and instantly categorizes it as either Legitimate or Fraudulent.

1.3 Why Credit Card Fraud Detection is a Machine Learning Problem:
Fraud detection is fundamentally an inductive pattern recognition problem:
1. High Dimensionality: Transactions are described by many numerical variables simultaneously (28 principal components capturing transaction latent features, plus monetary amount). Humans cannot visualize relationships in 29-dimensional space.
2. Subtle Non-Linear Boundaries: Fraudulent patterns often masquerade as normal activity, differing only through subtle combinations of mathematical variables that define an anomalous manifold.
3. Speed Requirements: Decisions must be calculated within milliseconds using algebraic dot products and kernel transformations.
4. Generalization: Rule-based systems (e.g., "if amount > $5000 flag fraud") fail because fraudsters easily circumvent static thresholds. Machine learning models generalize from historical patterns to detect novel attacks.

SECTION 2 — PROBLEM DEFINITION
================================================================================

2.1 The Nature of Fraud Detection:
Credit card fraud detection is formally defined as a supervised binary classification problem. Given a set of historical transactions with known outcomes, our goal is to estimate an unknown mapping function f: X -> Y where:
- The input space X is a subset of R^29 representing the continuous feature space of transactions.
- The label space Y = {0, 1} represents the discrete binary states:
  - Class 0 (y = 0): Legitimate Transaction — Authorized purchase executed by the genuine account holder.
  - Class 1 (y = 1): Fraudulent Transaction — Unauthorized, deceptive charge executed by an illegitimate entity.

2.2 Why Manual Detection Fails:
1. Transaction Velocity: Modern payment gateways process thousands of transactions per second. Human underwriters cannot review transactions in real time.
2. Cognitive Limitations: Fraudsters execute coordinated distributed attacks where individual transaction amounts appear benign (e.g., $15 to $50). The fraudulent signal is only apparent in high-dimensional PCA geometric projections.
3. Economic Cost of Latency: Delaying card authorization by even two seconds causes significant customer abandonment at point-of-sale terminals.

2.3 Why Machine Learning is the Industry Standard:
Machine learning algorithms:
- Learn non-linear functional boundaries directly from empirical data without manual rule authoring.
- Operate deterministically at sub-millisecond evaluation latencies once trained.
- Enable quantitative tuning between conservative models (prioritizing high recall to catch fraud) and permissive models (prioritizing high precision to minimize customer friction).

- What it does: Divides the data into 80% training data (454,904 samples) and 20% test data (113,726 samples).

  - Training Set: 227,452 Legit (50.0%) / 227,452 Fraud (50.0%)

- Code:
  X_train, X_test, y_train, y_test = train_test_split(

  )

6.5 Step 5: Feature Standardization with StandardScaler
- What it does: Normalizes every numerical feature so that it has a mean of zero (mu = 0) and unit variance (sigma = 1):
  z = (x - mu) / sigma
- Why we do it for SVM: Support Vector Machines find an optimal separating hyperplane by computing Euclidean distances (||w||) and inner products (x_i^T x_j). The feature Amount ranges from 0 to 24,039.93, whereas PCA features V1 to V28 have much smaller ranges. If left unscaled, Amount would dominate the distance metric.
- Why fit ONLY on training data: To prevent data leakage. The parameters mu (mean) and sigma (standard deviation) must be calculated exclusively from the training partition.
- Code:
  scaler = StandardScaler()
  X_train_scaled = pd.DataFrame(scaler.fit_transform(X_train), columns=X_train.columns, index=X_train.index)
  X_test_scaled = pd.DataFrame(scaler.transform(X_test), columns=X_test.columns, index=X_test.index)

Because the 2023 dataset is inherently class-balanced, no undersampling, SMOTE oversampling, or artificial class weighting (class_weight='balanced') is used.

SECTION 7 — MACHINE LEARNING ALGORITHM: SUPPORT VECTOR MACHINES (SVM)
================================================================================

7.1 Absolute Basics: Supervised Learning & Classification
- Supervised Learning: A branch of machine learning where an algorithm is trained on labeled input-output pairs (x_i, y_i), learning a mapping from input features to known target outputs.
- Classification: A supervised learning task where the target output variable is categorical rather than continuous. In our project, it is binary classification (y in {0, 1}).

7.2 What is a Support Vector Machine?
A Support Vector Machine (SVM) is a maximum-margin classifier. Given a set of points from two classes in an n-dimensional space, SVM finds a decision boundary that separates the classes while maximizing the distance between the boundary and the closest data points from either class.

7.3 Core Geometric Concepts:
1. Hyperplane: An (n-1)-dimensional flat affine subspace dividing an n-dimensional space into two halves. In our 29-dimensional space, the hyperplane is defined algebraically as:
   w^T x + b = 0
   where w in R^29 is the normal weight vector and b in R is the bias offset.
2. Margin: The geometric distance between the decision boundary and the closest training points on either side:
   Margin = 2 / ||w||
   SVM minimizes ||w||^2, which maximizes the margin 2 / ||w||. Maximizing the margin provides theoretical guarantees against overfitting.
3. Support Vectors: The critical training instances that lie exactly on the margin boundaries (w^T x_i + b = +/- 1). If any non-support-vector point is moved or removed, the hyperplane remains identical.
4. Kernel Function (K(x, x')): A mathematical function that computes the inner product of two vectors in a transformed feature space without explicitly calculating the transformation coordinates:
   K(x, x') = <phi(x), phi(x')> (The Kernel Trick).

7.4 The Linear SVM Kernel:
- Mathematical Form: K(x, x') = x^T x'
- How it works: Constructs a straight, planar decision boundary directly in the original 29-dimensional feature space.
- When it is useful: Computationally straightforward, produces an interpretable weight vector w, and works well when features have high dimensionality and classes are linearly separable.

7.5 The RBF (Radial Basis Function / Gaussian) Kernel:
- Mathematical Form: K(x, x') = exp(-gamma * ||x - x'||^2)
- How it works: Implicitly maps input vectors into an infinite-dimensional Hilbert space where complex, non-linear boundaries in 29 dimensions become linearly separable.
- Parameters Used in Project:
  1. C = 1.0 (Regularization Parameter): Controls the trade-off between maximizing the margin and minimizing training classification errors. A moderate C=1.0 provides balanced regularization without overfitting.
  2. gamma = 'scale' (Kernel Coefficient): Defines the influence radius of individual support vectors:
     gamma = 1 / (n_features * Var(X)) = 1 / (29 * 1.0) approx 0.0345.

SECTION 8 — MODEL IMPLEMENTATION
================================================================================

8.1 Actual Model Definitions in Code:
```python
from sklearn.svm import SVC

# 1. Linear SVM
linear_model = SVC(kernel="linear", cache_size=1000)

# 2. RBF SVM
rbf_model = SVC(kernel="rbf", C=1.0, gamma="scale", cache_size=1000)
```

8.2 Parameter Explanation:
- kernel="linear": Specifies the linear dot-product kernel.
- kernel="rbf": Specifies the Radial Basis Function Gaussian kernel.
- C=1.0: Standard soft-margin penalty.
- gamma="scale": Uses 1 / (n_features * X.var()) for the RBF Gaussian spread.
- cache_size=1000: Allocates 1,000 MB (1 GB) of RAM to cache kernel evaluations in the underlying LIBSVM C++ solver, speeding up convergence.

8.3 Core Methods Explained:
1. model.fit(X_train, y_train):
   Solves the convex quadratic programming dual optimization problem to estimate support vectors, dual weights alpha_i, and bias b.
2. model.predict(X_test):
   Generates discrete class labels (0 or 1) by evaluating the sign of the decision function. Returns 1 if score >= 0, and 0 if score < 0.
3. model.decision_function(X_test):
   Returns the raw, unthresholded continuous distance score: f(x) = sum(alpha_i * y_i * K(x_i, x)) + b. This is a geometric distance score, NOT a probability.

SECTION 13 — MODEL EVALUATION METRICS
================================================================================

13.1 Confusion Matrix Terminology:
- True Positive (TP): Fraud transactions correctly predicted as fraud.
- True Negative (TN): Legitimate transactions correctly predicted as legitimate.
- False Positive (FP): Legitimate transactions incorrectly flagged as fraud (Type I error / False Alarm).
- False Negative (FN): Fraud transactions incorrectly predicted as legitimate (Type II error / Missed Fraud).

13.2 Accuracy:
- Definition: Proportion of total predictions that were correct.
- Formula: Accuracy = (TP + TN) / (TP + TN + FP + FN)

13.3 Precision:
- Definition: Proportion of flagged transactions that were truly fraudulent.
- Formula: Precision = TP / (TP + FP)
- Banking Significance: Measures false alarms. High precision minimizes unnecessary customer account freezes.

13.4 Recall (Sensitivity):
- Definition: Proportion of actual fraud transactions that the model successfully caught.
- Formula: Recall = TP / (TP + FN)
- Banking Significance: Most critical metric in financial security. A missed fraud (FN) results in direct monetary theft.

13.5 F1-Score:
- Definition: Harmonic mean of Precision and Recall.
- Formula: F1 = 2 * (Precision * Recall) / (Precision + Recall)

13.6 ROC-AUC:
- Definition: Area Under Receiver Operating Characteristic curve. Measures ranking ability across all thresholds.
- Formula: Plots TPR (TP / (TP + FN)) vs FPR (FP / (FP + TN)).

13.7 PR-AUC:
- Definition: Precision-Recall Area Under Curve (Average Precision). Evaluates trade-off between Precision and Recall across thresholds.

SECTION 16 — WHY ACCURACY CAN BE MISLEADING (AND THE ROLE OF CLASS BALANCE)
================================================================================

16.1 The Accuracy Paradox in Imbalanced Datasets:
In datasets with severe class imbalance (such as 0.17% fraud in the 2013 ULB dataset), a dummy model predicting all transactions as legitimate achieves 99.83% accuracy while catching zero frauds. This is the Accuracy Paradox.

16.2 In Our 2023 Balanced Dataset:
In our active 2023 dataset, exactly 50% of transactions are legitimate and 50% are fraud. A dummy model achieves only 50.00% accuracy. Therefore, Accuracy (96.60% for Linear SVM, 99.71% for RBF SVM) is a valid, informative metric. However, banks still inspect Recall and Precision separately to balance false alarms against unintercepted fraud losses.

   Training an algorithm on labeled data pairs (x, y) to learn a functional mapping from inputs to target outputs.
3. What is classification?
   A supervised learning task where the target output variable is categorical.
4. What is binary classification?
   Classification with exactly two discrete classes (0 and 1).
5. Difference between classification and regression?
   Classification predicts categorical labels; regression predicts continuous numbers.
6. Why is fraud detection framed as classification?
   Because the operational decision is binary: approve (legitimate) or block/flag (fraud).
7. What dataset was used?
   Credit Card Fraud Detection Dataset 2023 from Kaggle.
8. How many transactions are in the dataset?
   568,630 transactions.
9. How many features are used?
   29 numerical features (V1 to V28, and Amount).
10. What happened to the id column?
    Dropped during preprocessing because it is an arbitrary row index with no predictive value.
11. What does Class 0 represent?
    A legitimate credit card transaction.
12. What does Class 1 represent?
    A fraudulent credit card transaction.
13. Is the dataset balanced or imbalanced?
    Balanced: exactly 50% Legitimate (284,315) and 50% Fraud (284,315).
14. What are V1 to V28?
    Principal Component Analysis (PCA) numerical components protecting cardholder privacy.
15. Can we know the exact real-world meaning of V1 or V14?
    No, because they are anonymized mathematical projections.
16. Is there a Time column in the 2023 dataset?
    No, only V1 through V28 and Amount are present.

18. Were there any duplicates?
    Exactly 1 duplicate row was identified and audited.

    To evaluate generalizability on unseen data and prevent overfitting.

    80% Training (454,904) and 20% Testing (113,726).

    To guarantee identical 50/50 class balance in both partitions.
22. Why set random_state=42?
    To ensure reproducible train-test splits.
23. Why is feature scaling necessary for SVM?
    SVM relies on distance calculations; unscaled features with large ranges (like Amount) would dominate the distance metric.
24. What scaler was used?
    StandardScaler (mean=0, std=1).
25. What is data leakage?
    Inadvertently using test set information during model training or preprocessing.
26. How did you prevent data leakage during scaling?
    By fitting the scaler strictly on the training set (fit_transform) and using transform on test data.
27. Did you apply undersampling or SMOTE?
    No, because the 2023 dataset is already balanced.
28. What is a Support Vector Machine?
    A supervised learning algorithm that finds an optimal hyperplane maximizing the margin between classes.
29. What is a hyperplane?
    An (n-1)-dimensional flat decision boundary separating an n-dimensional space (w^T x + b = 0).
30. What is the margin in SVM?
    The geometric distance between the decision boundary and the nearest data points (2 / ||w||).
31. Why does SVM maximize the margin?
    A wider margin provides theoretical guarantees against overfitting.
32. What are support vectors?
    The critical training instances lying on the margin boundaries that define the hyperplane.
33. If non-support vectors are removed, what happens?
    The hyperplane remains identical.
34. What is a kernel in SVM?
    A function that computes inner products in a higher-dimensional space without evaluating coordinates explicitly (Kernel Trick).
35. What kernels did you implement?
    Linear kernel and Radial Basis Function (RBF) kernel.
36. How does the Linear kernel work?
    Computes direct dot products x^T x', creating a flat decision boundary in 29 dimensions.
37. How does the RBF kernel work?
    Computes Gaussian radial distance exp(-gamma * ||x - x'||^2), mapping points into infinite-dimensional space.
38. What does parameter C do in SVM?
    Regularization parameter balancing margin width against training classification errors.
39. What does gamma do in RBF SVM?
    Defines the influence radius of individual support vectors.
40. What value of gamma was used?
    gamma='scale' (1 / (n_features * Var(X))).
41. What does model.predict() return?
    Discrete predicted class labels (0 or 1).
42. What does model.decision_function() return?
    Raw continuous signed distance to the separating hyperplane.
43. Is the decision score a probability?
    No. It is an unbounded geometric distance score, not a probability.
44. What is a Confusion Matrix?
    A table showing True Negatives, False Positives, False Negatives, and True Positives.
45. What is a False Positive in fraud detection?
    A legitimate transaction incorrectly flagged as fraud (false alarm).
46. What is a False Negative in fraud detection?
    A fraudulent transaction missed by the model.
47. Which error is more costly in banking?
    False Negatives, because undetected fraud leads directly to financial loss.
48. What is Recall?
    The proportion of actual fraud transactions successfully caught (TP / (TP + FN)).
49. What is Precision?
    The proportion of flagged transactions that were truly fraudulent (TP / (TP + FP)).
50. What is the F1-Score?
    The harmonic mean of Precision and Recall.

SECTION 21 — 20 TRICKY PROFESSOR QUESTIONS & ANSWERS
================================================================================

1. Why choose SVM over Logistic Regression or Random Forest?
   SVM is a core algorithm for studying convex optimization and maximum-margin theory. It is effective in moderately high-dimensional spaces (29 continuous numerical features) where margin maximization provides strong generalization guarantees.
2. Why did RBF SVM achieve higher accuracy than Linear SVM?
   Because the boundary separating fraud from legitimate transactions is non-linear. The Linear SVM is constrained to a flat hyperplane, whereas RBF constructs non-linear Gaussian decision boundaries.
3. Why did RBF SVM train in 2.9 minutes while Linear SVM took 20.4 minutes?
   In LIBSVM's Sequential Minimal Optimization (SMO) solver, the RBF kernel easily separates the balanced clusters in its transformed space with fewer iterations. Linear SVM struggled to find a flat planar separator in 29 dimensions, requiring more active-set iterations.
4. What happens if you scale data before train-test split?
   Data leakage occurs: test set statistics (mean and variance) leak into the training process.
5. Why not scale only Amount since V1-V28 are PCA components?
   Empirical standard deviations of V1-V28 vary slightly across samples. Applying StandardScaler to all 29 features ensures equal contribution to the distance metric.
6. Difference between C=0.01 and C=100?
   Small C tolerates more margin violations for a wider margin (underfitting risk). Large C penalizes violations heavily, forcing a narrower margin (overfitting risk). We used C=1.0 as a balanced default.
7. Mathematical meaning of the decision score?
   The signed orthogonal Euclidean distance from the transaction point to the separating hyperplane: f(x) = w^T phi(x) + b.
8. How does the Streamlit app know the transaction Amount if it was scaled?
   It uses the saved scaler.joblib to call inverse_transform, reversing z-score standardization (x = z * sigma + mu) to retrieve the original monetary amount.
9. Why specify cache_size=1000?
   Allocates 1,000 MB of RAM to cache kernel evaluations in the SMO optimization loop, speeding up convergence.
10. How do you know the model didn't memorize training data?
    Evaluated on an untouched test set of 113,726 transactions that was held out before training. RBF SVM achieved 99.71% accuracy on this unseen test data.
11. Why use Stratified sampling?
    Guarantees that both training and test sets have identical 50/50 class balance.
12. Geometric interpretation of a Support Vector?
    A training instance lying on the margin boundary (w^T phi(x) + b = +/- 1) or violating the margin.
13. Is Accuracy misleading in your project?
    In imbalanced datasets it is, but here exactly 50% is fraud and 50% is legitimate, so accuracy is a valid high-level metric.
14. Why didn't you use class_weight='balanced'?
    Because the dataset is already 50/50 balanced, so the calculated weights would both be 1.0, making the parameter redundant.
15. What if a new transaction has an Amount larger than any training amount?
    StandardScaler scales it using the training mean and standard deviation, and SVM projects it along the normal vector w.
16. Why drop id?
    It is an arbitrary row index with no causal or statistical relationship to fraud.
17. Can SVM handle missing values natively?
    No. Missing coordinates prevent distance calculations. The dataset has 0 missing values.
18. How does Streamlit demonstrate correct predictions and misclassifications?
    By sampling real transactions from the test set where the model's prediction matches ground truth or differs from ground truth.
19. Difference between ROC-AUC and PR-AUC?
    ROC-AUC plots TPR vs FPR (which includes TN). PR-AUC plots Precision vs Recall and focuses directly on the minority/positive class trade-off.
20. Why serialize using joblib instead of pickle?
    joblib is optimized for serializing large NumPy arrays and Scikit-Learn estimators efficiently.

model = SVC(kernel="rbf", C=1.0, gamma="scale", cache_size=1000)

y_pred = model.predict(X_test)
